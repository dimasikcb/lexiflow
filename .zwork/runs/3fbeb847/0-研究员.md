# 2. Рекомендация (высокая уверенность)

**Рекомендация: упрощённый FSRS-6 — фиксированные официальные параметры, желаемое удержание (desired retention) 0.9, без оптимизатора. Сохранить 4 кнопки, шаги обучения и машину состояний. Не «точный FSRS с оптимизацией» и не улучшенный SM-2.**

Обоснование по источникам (все — официальные,访问 2026-10-05):

1. **Точность.** Официальный бенчмарк open-spaced-repetition (9 999 коллекций Anki, ~350 млн оценок): FSRS-6 (21 параметр) — LogLoss 0.3460, RMSE(bins) 0.0653, AUC 0.7034; против FSRS-4.5 (17 п.) 0.3624/0.0764/0.6893 и FSRS v4 0.3726/0.0838/0.6853 (https://github.com/open-spaced-repetition/srs-benchmark, README, таблица «Without same-day reviews»). SM-2 в таблице нет; классические бейзлайны вокруг него (DASH 0.3682, HLR 0.4694, константа AVG 0.3945) — хуже даже неоптимизированного FSRS («FSRS-7 default param.» 0.3629/0.0910). Анки официально включил FSRS в ядро (раздел «FSRS» в мануале колод: https://docs.ankiweb.net/deck-options.html).
2. **Неоптимизированный FSRS почти не теряет.** Разница optimized/defaulт в бенчмарке: FSRS-7 0.3437 vs 0.3629 LogLoss — выигрыш от пер-юзера оптимизации мал. Для офлайн-PWA без бэкенда оптимизатор (обучение 21 параметра) не потянуть разумно, а основную пользу даёт сама модель + персональная настройка одной ручки — желаемого удержания (desired retention).
3. **Ровно под 4-5 кнопок.** Шкала FSRS — Again/Hard/Good/Easy (ts-fsrs `Rating`), официальное FAQ: работать только с Again+Good — нормально и иногда точнее (https://faqs.ankiweb.net/frequently-asked-questions-about-fsrs.html, Q2).
4. **Совместимость и офлайн.** Формулы полностью открыты и элементарны (~150-250 строк ES5): официальный референс — ts-fsrs, файлы `packages/fsrs/src/algorithm.ts`, `constant.ts`, `default.ts` (https://github.com/open-spaced-repetition/ts-fsrs; бейдж FSRS-v6, `default_request_retention = 0.9`, `maximum_interval = 36500`, MIT). Зависимость не нужна — тащить ts-fsrs целиком (TS/ESM, Node ≥ 20) не стоит, достаточно реализовать формулы; данные мигрируют тривиально (§3).
5. **Почему не улучшенный SM-2:** все «заплатки» SM-2 (антисерийная аджастмент ease, реверт均值) — эвристики; FSRS даёт то же управление одной осмысленной ручкой (desired retention: интервал-множитель ×1.91 при 0.85, ×1.00 при 0.90, ×0.40 при 0.95 — вычислено по формуле из `algorithm.ts`) и честно моделирует забывание (интервал после провала зависит от D, S, R, а не «сброс в 1 день»). Сравнение поведения интервалов SM-2 vs FSRS поOfficial таблице: https://github.com/open-spaced-repetition/fsrs4anki/wiki (страница «Compare Anki's built-in scheduler and FSRS»).

Мелкие официальные ориентиры: первые интервалы FSRS длиннее SM-2, у зрелых карточек — короче (Anki FSRS FAQ, Q1); оптимальное desired retention около 0.9, выбор между нагрузкой и знанием — вики «The Optimal Retention» (fsrs4anki). FSRS-7 новее, но в стабильном ts-fsrs ещё FSRS-6 — берём v6.

# 3. План внедрения (сигнатуры, формулы, миграция)

## 3.1. Формулы FSRS-6 (полные, для кодера)

Обозначения: `G` — оценка 1..4 (Again/Hard/Good/Easy), `S` — стабильность (дни; интервал при R=90%), `D` — сложность (1..10), `R` — удержание (вероятность вспомнить), `t` — дней с последнего ответа. `w` — 21 параметр. Источник формул: `ts-fsrs/packages/fsrs/src/algorithm.ts` + wiki awesome-fsrs «The Algorithm» (FSRS-6).

**Параметры по умолчанию (официальные, `constant.ts → default_w`):**
```
w = [0.212, 1.2931, 2.3065, 8.2956, 6.4133, 0.8334, 3.0194, 0.001,
     1.8722, 0.1666, 0.796, 1.4835, 0.0614, 0.2629, 1.6483, 0.6014,
     1.8729, 0.5425, 0.0912, 0.0658, 0.1542]
```
(это же — «Default parameters» FSRS-6 в wiki; последние 4 — short-term/decay для FSRS-6; чистый w17-набор FSRS-4.5 при желании: `[0.4872, 1.4003, 3.7145, 13.8206, 5.1618, 1.2298, 0.8975, 0.031, 1.6474, 0.1367, 1.0461, 2.1072, 0.0793, 0.3246, 1.587, 0.2272, 2.8755]`, но рекомендую сразу 21.)

**1) Кривая забывания** (decay = −w₂₀):
```
FACTOR = exp(ln(0.9) / decay) − 1          // = e^(−ln0.9/w20) − 1; при w20=0.1542 FACTOR ≈ 0.98055249
R(t, S) = (1 + FACTOR · t / S) ^ decay      // инвариант: R(S, S) = 0.9
```

**2) Интервал под желаемое удержание DR** (`request_retention`, по умолчанию 0.9):
```
m(DR) = (DR^(1/decay) − 1) / FACTOR         // intervalModifier; m(0.9)=1, m(0.85)≈1.906, m(0.95)≈0.402
I(DR, S) = round( clamp( S · m(DR), 1, maxInterval ) )
```

**3) Инициализация после первого ответа:**
```
S₀(G) = max( w[G−1], 0.1 )                                  // Again 0.212, Hard 1.2931, Good 2.3065, Easy 8.2956
D₀(G) = clamp( w4 − exp((G−1) · w5) + 1, 1, 10 )            // ≈ 6.4133, 5.1121, 2.1177, 1 (G=4 клампится)
```

**4) Сложность после ответа** (linear damping + mean reversion к D₀(4)):
```
ΔD = −w6 · (G − 3)
D′ = D + ΔD · (10 − D) / 9
D″ = clamp( w7 · D₀(4) + (1 − w7) · D′, 1, 10 )
```
⚠ Расхождение в источниках, зафиксировать: wiki-текст для FSRS-5/6 называет целью реверта D₀(4); код ts-fsrs (`next_difficulty`) действительно ревертирует к `init_difficulty(Rating.Easy)` = D₀(4). С дефолтным w D₀(4)=1 → при w7=0.001 эффект мизерный. Проверить на тест-векторах py-fsrs при валидации (поставил в §4 тест-вектор). (определённо по коду; wiki согласен)

**5) Стабильность после успешного ответа** (G ∈ {2,3,4}, t > 0):
```
S′ = S · ( 1 + e^{w8} · (11 − D) · S^{−w9} · (e^{w10·(1−R)} − 1) · [G=2: w15] · [G=4: w16] )
S′ = clamp(S′, 0.001, 36500)
```

**6) Стабильность после провала** (G = 1, t > 0):
```
S′f = w11 · D^{−w12} · ((S+1)^{w13} − 1) · e^{w14·(1−R)}
S′  = min( S′f, S / e^{w17·w18} ), floor 0.001      // верхний кламп из ts-fsrs next_state (enable_short_term=true)
```

**7) В тот же день (t = 0, short-term):**
```
SInc = S^{−w19} · e^{w17 · (G − 3 + w18)};  для G ≥ 2: SInc = max(SInc, 1)
S′ = clamp(S · SInc, 0.001, 36500)
```

**8) Границы:** S ∈ [0.001, 36500], D ∈ [1,10], интервал ≥ 1 дня, ≤ `maxInterval`; fuzz по умолчанию выключен (`default_enable_fuzz = false`) — оставляем выключенным (детерминизм для тестов).

6. **Рост S:** цепочка GOOD даёт строго растущий S с убывающим приростом (SInc→1); провал даёт `S′ < S` и `S′ ≤ S/e^(w17·w18)`; `lapses+1`, leech на 8-м провале сохраняется.
7. **Due не в прошлом:** из review при GOOD/HARD/EASY всегда `due > now` (интервал ≥ 1 дня), в т.ч. у сильно просроченных карточек (R маленькое → большой S′ — «долг не наказывается», свойство 3 из wiki).
8. **Границы:** интервал ≤ maxInterval; S ∈ [0.001, 36500]; D ∈ [1,10] (экстремальные входы).
9. **Same-day:** два ответа в один день — t=0 ветка; same-day AGAIN уменьшает S, same-day GOOD/EASY не уменьшают.
10. **Миграция:** review-карточка `{interval:25, ease:2.5}` → `{stability:25, difficulty:6}`; ease 4 → D 3; ease 1.3 → D 8.4; idempotent (повторный вызов не меняет); learning-карточка сохраняет step/due; JSON round-trip; старые поля ease/interval на месте (CSV/статистика).
11. **Чистота и совместимость:** `answer` не мутирует card.srs; `preview[g]` совпадает с label от `answer(g)`; структура результата `{srs, intervalMs, label, stateFrom, stateTo, leech}` неизменна; `scheduler:'sm2'` проходит все существующие SRS-ассерты без правок ожиданий.
12. **Тест-вектор для валидации формул:** зафиксировать 3-4 конкретных сценария (например, отзыв `D=2.1177, S=2.3065, t=2.3065, GOOD` → ожидаемый S′/интервал), посчитанные эталонной реализацией ts-fsrs (один раз прогнать локально `npx ts-fsrs` или py-fsrs и вшить числа с точностью 1e-4) — это ловит расхождения вроде реверта к D₀(4) (§3.1.4).
