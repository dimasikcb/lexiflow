## 2. Модель (веб-проверка)

**Рекомендация: `Xenova/mms-tts-rus`** — https://huggingface.co/Xenova/mms-tts-rus
- Карточка: «facebook/mms-tts-rus with ONNX weights to be compatible with Transformers.js», пример: `pipeline('text-to-speech', 'Xenova/mms-tts-rus')` → `{audio: Float32Array, sampling_rate: 16000}` (фактически прочитано с карточки). Один фиксированный голос (MMS не даёт выбора спикеров) — согласуется с текущим UI ttsnet, где выбора голоса тоже нет.
- Файлы в `onnx/` (проверено на странице tree/main/onnx, каталог 211 МБ): `model_quantized.onnx` **38,4 МБ**, `model_fp16.onnx` 58,1 МБ, `model.onnx` 114 МБ. quantized загружается по умолчанию в v2.
- CORS: transformers.js в браузере сам тянет файлы с `huggingface.co/.../resolve/...` и кэширует их в браузерном Cache API (`env.useBrowserCache`) — это штатный механизм библиотеки (README 2.7.0, раздел Settings), т.е. URL модели пригоден для прямого fetch с прогрессом.

Отсечение кандидатов:
- **Kokoro-82M**: русского нет. Карточка https://huggingface.co/hexgrad/Kokoro-82M: v1.0 — «8 & 54» (8 языков, 54 голоса), ru в списке отсутствует. Отпадает.
- **Piper**: официального браузерного порта под onnxruntime-web/transformers.js нет; голос `ru_RU` в rhasspy/piper-voices существует, но запускается через отдельный wasm-рантайм sherpa-onnx — другой стек, не «модель + ort-web». Готовый файл взять неоткуда → не кандидат (низкая уверенность, только по поисковой выдаче).
- **Версия transformers.js**: docs v3 (главная, стабильная v3.8.1) в списке задач пайплайна `text-to-speech` **не содержат**; README ветки 2.7.0 содержит `text-to-speech` ✅ (раздел Tasks/Audio). → **Пиновать `@xenova/transformers@2.7.0`** (jsdelivr), не v3.

## 3. Архитектура (минимум изменений)

Новый модуль `js/ttsmodel.js` по образцу ttsnet.js + ветка в диспетчере speech.js:

```
downloadModel(modelId, onProgress)      // fetch resolve-URL со стримингом, кладём в Cache 'lexiflow-tts-v1'
                                        // (ключ = URL файла), onProgress({received, total}) из content-length
isDownloaded(modelId) / removeModel()   // match/put/delete в том же кэше
ensureWorker(modelId)                   // новый Worker: importScripts jsdelivr @xenova/transformers@2.7.0,
                                        // wasmPaths на jsdelivr (файлы добавить в precache sw.js для офлайна),
                                        // env.allowLocalModels=false; ONNX-файл воркер берёт из переданного blob/URL
synthesize(text) -> {audio: Float32Array, sampling_rate: 16000}
                                        // -> OfflineAudioContext.createBuffer -> play как в ttsnet.play()
```
Диспетчер в speech.js: в начале `speak()` — если `settings.tts.engine === 'model'` и модель готова → `ttsmodel.synthesize(chunks)` (текст уже нарезан), при ошибке/отсутствии модели → существующий путь (Web Speech/ttsnet). Настройки: `settings.tts = { engine: 'webspeech'|'model', modelId: 'Xenova/mms-tts-rus' }` — `updateSettings` уже принимает вложенные объекты (паттерн `ttsNet` в store.js).

## Риски (кратко)
- quantized-версия MMS звучит заметно хуже fp32 — возможно, поставить fp16 (58 МБ) как рекомендуемую; выбор качества = отдельный `modelId`.
- Первый синтез на слабом телефоне может занимать секунды — синтез только в Worker, UI не блокируется.
- V3-миграция transformers.js вернёт TTS позже — при апгрейде держать пин 2.7.0.
