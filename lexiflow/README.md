# LexiFlow — тренажёр иностранных слов

Веб-приложение для изучения иностранных слов: колоды карточек, интервальное повторение
(spaced repetition), тренировки и тесты, статистика, импорт/экспорт. Работает как обычный
сайт и как устанавливаемое PWA-приложение с офлайн-режимом.

Написано без единой внешней зависимости: чистый HTML + CSS + JavaScript.
Все данные хранятся **только на устройстве** (localStorage) — ничего не отправляется на сервер.

## Возможности

### Колоды и карточки
- Создание, редактирование, дублирование и удаление колод; цвет, описание, языковая пара.
- Карточка: слово, перевод, транскрипция, несколько примеров употребления с переводом,
  заметка, теги, озвучивание, постановка на паузу.
- Поиск, фильтры по состоянию (новые / в обучении / повторение / к повторению / трудные),
  сортировка, массовые операции в «Словаре»: перенос в другую колоду, сброс прогресса,
  пауза, удаление, экспорт выбранного.

### Интервальное повторение
Алгоритм, близкий к Anki/SM-2, с настраиваемыми параметрами для каждой колоды:
- шаги обучения и шаги после забывания (в минутах);
- интервал выпуска и интервал для оценки «Легко»;
- стартовый ease-фактор, бонус за «Легко», множитель «Трудно»;
- модификатор интервала, минимальный/максимальный интервал, остаток интервала после забывания;
- лимиты новых карточек и повторений в день, порог «трудной» карточки (leech).

Перед ответом кнопки оценки показывают будущий интервал («1 мин», «4 д», «2,5 мес»).
Есть отмена последнего ответа (кнопка или `Ctrl+Z`), досрочный показ карточек обучения
с таймером, дневные лимиты и продолжение сессии после завершения.

### Режимы тренировки
| Режим | Описание |
|---|---|
| Карточки | классический флип: смотрим слово, вспоминаем, оцениваем себя |
| Выбор варианта | 4 варианта перевода, дистракторы берутся из других слов |
| Ввод перевода | ввод с клавиатуры, сравнение с учётом регистра и диакритики, «почти верно» при опечатке, подсветка различий |
| Аудирование | слово произносится синтезом речи, нужно выбрать перевод (медленный/обычный темп) |
| Микс | режимы чередуются по ходу сессии |

Направление переключяется: «слово → перевод», «перевод → слово» или в обе стороны.

### Тестирование
Отдельный режим без влияния на интервалы: выбирается количество вопросов, режим и направление.
В конце — результат (верных ответов, время, скорость), список ошибок и кнопка
«Повторить ошибки».

### Статистика
- Серия дней подряд, повторений сегодня, цель дня, точность за 30 дней, время в изучении.
- График активности за 30 дней (повторения и новые слова).
- Тепловая карта активности за 26 недель.
- Прогноз повторений на 14 дней вперёд.
- Распределение карточек по состояниям (кольцевая диаграмма).
- Таблица по колодам и список самых «трудных» слов.
Все графики нарисованы собственным SVG-кодом — внешние библиотеки не нужны и не ломают офлайн.

### Импорт и экспорт
- **Экспорт:** полная резервная копия JSON, JSON отдельной колоды, CSV (все слова или выбранные).
- **Импорт:** JSON-бэкап (слияние или полная замена данных), CSV/TSV с заголовками,
  простые строки вида `слово - перевод` (`-`, `=`, `:`, табуляция, запятая).
  Автоопределение разделителя и колонок, пропуск дубликатов, перестановка колонок,
  выбор целевой колоды или создание новой.
- **Колонка «Колода».** Если в CSV есть колонка с названием колоды (как в нашем экспорте),
  строки раскладываются по своим колодам: существующие находятся по имени, отсутствующие
  создаются. Так работает круговой рейс «экспорт → импорт» без потери структуры.
- **Слияние без мусора.** При импорте JSON колоды создаются только для реально добавленных
  слов, поэтому повторный импорт своей же копии не плодит пустые колоды-дубликаты.

#### Примеры употребления на двух языках

Импорт понимает пример вместе с его переводом — и не один, а сколько угодно на карточку.

| Способ | Как выглядит в файле |
| --- | --- |
| Пара колонок | `Пример` + `Перевод примера` |
| Пронумерованные колонки | `Пример 2` + `Перевод примера 2`, `Пример 3` + `Перевод примера 3`… |
| Английские заголовки | `example` / `example translation`, `example 2` / `example translation 2` |
| Несколько примеров в одной ячейке | разделитель `\|\|` (двойная вертикальная черта) или перевод строки внутри кавычек |
| Без заголовков | 4-я колонка — пример, 5-я — перевод примера |

Заголовки распознаются по смыслу: `пример`, `примеры`, `example`, `sentence`, `предложение`,
`перевод примера`, `example translation`. Если переводов меньше, чем примеров, единственный
перевод достаётся первому примеру, а остальные остаются без перевода (ничего не дублируется).

```csv
Слово,Перевод,Транскрипция,Пример,Перевод примера,Пример 2,Перевод примера 2
brisk,бодрый,brɪsk,"A brisk walk helps.","Бодрая прогулка помогает.","The air was brisk.","Воздух был свежим."
```

При экспорте в CSV парные колонки добавляются автоматически — столько, сколько нужно самому
«богатому» на примеры слову, поэтому круговой рейс «экспорт → импорт» ничего не теряет.
В списке слов показывается первый пример с переводом и счётчик `+N` остальных.

#### Список слов от нейросети (экран «Промпт для нейросети», `#/ai`)

Слова не обязательно набирать руками. Отдельный экран собирает готовый запрос
для ChatGPT, Gemini, Claude или DeepSeek:

- **Параметры** — язык, тема, уровень, количество слов, один или два примера на слово,
  разбивка по колодам. Промпт пересобирается на каждое изменение.
- **Готовый промпт** — поле, которое растёт под текст. Его можно править руками,
  скопировать одной кнопкой или скачать как `prompt-lexiflow.txt`.
- **Инструкция** — три шага: скопировать → сохранить ответ как `words.csv` (UTF-8, без
  markdown-обёртки) → загрузить в «Импорт / экспорт». Там же кнопки «Перейти к импорту»,
  «Скачать пример CSV» и справка по колонкам.
- **Если импорт не сработал** — пять типовых причин и что делать.

Промпт описывает ровно тот формат, который понимает `store.importTabular()`:
заголовки `Слово,Перевод,Транскрипция,Пример,Перевод примера`, кавычки для полей
с запятыми, отсутствие markdown-разметки. Это проверяется тестом: заголовки берутся
из собранного промпта и скармливаются импортёру.

Те же формулировки (и ещё три варианта — с двумя примерами, с несколькими колодами
и в формате JSON) лежат в `import-templates/prompt-for-ai.md`. Рядом —
`import-templates/sample-en-ru.csv`, рабочий пример на 10 слов: его можно импортировать
как есть для проверки.

### Озвучивание
- Голос подбирается автоматически по качеству: нейросетевые и облачные голоса
  (в названии есть Natural, Neural, Premium, Google, Siri) получают приоритет над
  системными «compact» и роботизированными (eSpeak). Шутливые голоса вроде Bells
  или Zarvox отодвигаются в конец списка.
- В настройках можно закрепить конкретный голос для каждого языка, который есть в колодах.
  Пометка «онлайн» означает, что голос синтезируется на сервере и в офлайне недоступен.
- Темп (0,5–1,4×), тон (0,6–1,4) и громкость (30–100 %) регулируются ползунками.
- Между репликами выдерживается пауза в 70 мс: без неё Chrome обрывает начало следующей
  фразы — это и есть тот самый «щелчок» и проглоченное первое слово.
- Ссылка на объект речи удерживается в памяти, иначе сборщик мусора обрывает фразу
  на полуслове; список голосов ожидается до 700 мс, чтобы первая фраза не читалась
  случайным голосом по умолчанию.
- Длинные фразы периодически «подталкиваются» (pause/resume), потому что Chrome и Edge
  ставят их на паузу примерно через 15 секунд и не всегда дочитывают.
- Субтитры: слово, которое произносится прямо сейчас, подсвечивается на карточке
  (событие `onboundary`). Если браузер границы слов не сообщает — Safari — подсветка
  идёт по расчётному темпу речи, поэтому синхронизация есть везде.
- Повторное нажатие на кнопку «Прослушать» останавливает чтение.
- **Уход с экрана останавливает речь.** Синтез речи не замолкает сам, когда вкладка
  уходит в фон, а «подталкиватель» длинных фраз вдобавок будит его через
  pause/resume каждые 9 секунд — из-за этого слово продолжало звучать из свёрнутого
  окна или из другого приложения. Теперь `visibilitychange → hidden` и `pagehide`
  вызывают остановку. Возврат на экран чтение не возобновляет.
- **Голоса проверяются до начала тренировки.** Если для языка колоды в системе
  нет голоса или он механический, над карточкой появляется блок с объяснением и
  кнопкой «Настройки озвучки». Иначе человек нажимает 🔊, ничего не слышит и
  решает, что приложение сломалось. Отказ запоминается по набору языков, поэтому
  блок не мозолит глаза: он вернётся только если в тренировке появится новый язык.

#### Качественная озвучка: своя база и докачка из интернета
Если нормального голоса в системе нет (а в Windows это обычное дело: для английского
и немецкого голосов там может не быть вовсе, а русские Irina и Pavel звучат механически),
приложение не ограничивается системным синтезом. Порядок такой:

1. **Своя база** — готовые MP3 внутри приложения (`audio/`, опись в `audio/manifest.json`).
   Собирается один раз инструментом `tools/build-audio-pack.js`. Не нужно ни интернета,
   ни Cache API: работает сразу после первой установки и в офлайне.
2. **Кэш браузера** — то, что приложение уже докачало раньше (Cache API `lexiflow-audio-v1`).
3. **Интернет** — фраза скачивается с бесплатного сервиса `code.responsivevoice.org`
   и сразу кладётся в кэш, поэтому второй раз звучит из кэша.
4. **Системный голос** — если ничего из этого не сработало.

Переключение автоматическое: решение принимает `App.ttsnet.available(lang)`, который
смотрит на качество системного голоса. При хорошем голосе (нормальном или нейросетевом)
ни файлы, ни сеть не используются вовсе — текст фраз никуда не уходит.

Путь один и для кнопки 🔊, и для автопроигрывания (`speakAuto()` в `js/views/study.js`):
без этого карточка «сама» говорила системным голосом, а по кнопке — нормальным.
Предупреждение «скачай качественную озвучку» показывается, только когда язык
действительно нечем озвучить (`voiceAdvice()` → `filesCover()`); если фразы звучат
из файлов, блока нет.

Честные ограничения (проверено 2026-09-21):
- Сторонний сервис бесплатный и может отказать или измениться — тогда остаётся
  системный голос. Выбор голоса у него не работает: `Russian Female` и `Russian Male`
  дают байтово одинаковый файл, поэтому в интерфейсе выбирать нечего, только язык.
- Когда играет файл, подсветки слов нет: у MP3 нет события `onboundary`, а подсветка
  «на глазок» расходилась бы со звуком.
- При включённой сетевой озвучке текст фраз уходит на сторонний сервис. Режим
  включён по умолчанию, потому что включается только при плохом системном голосе;
  выключить его можно в настройках — тогда останутся файлы пакета и системный голос.

### Синхронизация между устройствами
- Одна база слов и прогресса на компьютере и телефоне через **секретный GitHub Gist**.
  Провайдер выбран потому, что его API отдаёт CORS-заголовки (`Access-Control-Allow-Origin: *`)
  и поэтому вызывается прямо из браузера — своему серверу у проекта взяться неоткуда.
  Yandex.Disk WebDAV, например, CORS не отдаёт, и подключить его из браузера нельзя.
- **Хранилище создаётся автоматически — токен не нужен.** Приложение само создаёт
  секретный Gist и начинает синхронизацию. Токен GitHub нужен только если вы
  хотите вручную контролировать доступ.
- Слияние данных честное, а не «кто последний, тот и прав»:
  - у каждой колоды и карточки есть `updatedAt`, побеждает более свежая правка;
  - удаления запоминаются «надгробиями» (`tombstones`), иначе удалённая на телефоне
    карточка воскресала бы с компьютера;
  - журнал повторений объединяется, а не перезаписывается;
  - настройки сравниваются по `settingsUpdatedAt`, при равенстве побеждает локальная версия.
- Карточка, чья колода исчезла, не пропадает, а переезжает в раздел без колоды.
- Автосинхронизация по таймеру и при возвращении в приложение, плюс кнопка «Синхронизировать сейчас».
- **Правки приезжают в реальном времени**: пока вкладка на экране, облако
  опрашивается каждые **15 секунд** (`App.sync.autoInterval()`). Удалили карточку
  на телефоне — на компьютере она исчезает сама, без ручной синхронизации и
  перезагрузки. В фоне браузер режет таймеры, поэтому там интервал остаётся
  пятиминутным, а на возвращение на экран работает отдельное правило.
- Экран обновляется только когда из облака пришло что-то новое (сравнивается
  отпечаток данных) и только когда это никого не прервёт: идущая тренировка,
  открытый диалог и незаконченный ввод не перерисовываются
  (`App.sync.shouldRefreshOnRemote()`).

#### Чужие правки приезжают при возвращении в приложение
Удаление на компьютере должно исчезнуть на телефоне — но для этого телефону надо
ещё и **забрать** это изменение. Здесь была та же ловушка, что и с отправкой:
таймеры в фоне стоят, а правило «прошло пять минут» на телефоне не наступало
никогда — приложение открывают и закрывают постоянно.

Теперь данные забираются в двух случаях:

- **при запуске приложения** — через 1,5 секунды после старта, не дожидаясь
  пятиминутного интервала. Это самый частый случай на телефоне;
- **при возвращении в приложение**, если оно отсутствовало дольше 45 секунд
  (короткое переключение вкладки сеть не дёргает), либо если с прошлого обмена
  прошло больше пяти минут.

Решение вынесено в чистую функцию `shouldSyncOnResume`, поэтому проверяется
тестами без ожидания таймеров, а в браузерном тесте отдельно проверяется
холодный старт с подменённой сетью: приложение обязано само прочитать хранилище.

#### Удаление уезжает сразу, а не «когда-нибудь»
Обычная правка отправляется через 5 секунд после изменения — чтобы каждая
нажатая карточка не дёргала сеть. **Удаление отправляется через 0,4 секунды**,
и вот почему.

Таймер живёт только в открытой вкладке, а мобильные браузеры замораживают
таймеры сразу, как только страница уходит в фон. Получалось так: колоду удаляют
на телефоне, человек тут же блокирует экран — и отложенная отправка не успевает
уехать. Надгробие остаётся лежать на телефоне, компьютер о нём не знает и
спокойно показывает «удалённую» колоду дальше. Именно это и выглядело как
«удалил на телефоне, а на компьютере осталась».

Поэтому удаление, помимо короткой задержки, досылается ещё двумя способами:

- при уходе страницы в фон или при её закрытии (`pagehide`, `visibilitychange`)
  запрос отправляется немедленно и помечается `keepalive` — браузер доводит его
  до конца уже во время закрытия;
- если отправить не удалось (нет связи), правка не теряется: приложение помнит
  о ней и отправляет при первой возможности, а в панели синхронизации пишет
  «Есть неотправленные правки».

Проверка простая: удаление должно оказаться в облаке меньше чем за секунду —
это отдельный тест, а не обещание.

#### «Удалить все данные» тоже удаляет, а не откладывает
Кнопка на экране «Данные» стирает колоды, слова и статистику **и в облаке тоже**:
на каждую запись ставится надгробие, а токен синхронизации остаётся на месте
(иначе отправлять надгробия было бы некуда). Раньше было иначе: очистка сносила
и настройки, синхронизация отключалась, а при следующем обмене всё возвращалось
из хранилища — то есть удалённое «само приезжало обратно». Если нужно стереть
данные только на одном устройстве, сначала отключите синхронизацию — диалог
об этом прямо предупреждает.

#### Подключение второго устройства
Порядок важен, иначе данные не встретятся:

1. **На первом устройстве** — вставить токен и нажать «Создать хранилище».
   Панель покажет **код хранилища** (идентификатор гиста) и кнопку «Скопировать».
2. **На втором устройстве** — вставить *тот же* токен, вставить код хранилища и нажать
   «Подключиться к хранилищу». Приложение проверит токен, найдёт гист по коду и сразу
   заберёт данные — перезапуск и ручная синхронизация не нужны.

Без поля кода второе устройство молча создало бы **своё** хранилище: статус был бы
«подключено», ошибок бы не было, а два устройства так и писали бы каждое в своё. Поэтому
код проверяется отдельно, а на неизвестный код панель отвечает «Хранилище с таким кодом
не найдено» и ничего не сохраняет.

Код хранилища — не секрет (в отличие от токена): сам по себе он доступа не даёт,
запись в гист возможна только с токеном владельца. Оба устройства должны быть
под одним аккаунтом GitHub, потому что токен и код проверяются вместе.

### Напоминания
- Одно уведомление в день в выбранное время, опционально — только если есть карточки к повторению.
- Пока вкладка открыта, проверка идёт раз в минуту. Когда приложение закрыто, работает
  **Periodic Background Sync**: страница кладёт сводку в IndexedDB, а service worker читает
  её оттуда (localStorage сервис-воркеру недоступен) и показывает уведомление.
- Честная оговорка: без push-сервера гарантировать уведомление при закрытом приложении
  нельзя — Periodic Background Sync поддерживается не всеми браузерами и не даёт точного
  времени. Это напоминание, а не будильник.
- Клик по уведомлению открывает приложение сразу на экране тренировки.
- Сводка для service worker уходит в IndexedDB **немедленно при уходе в фон**, а не по таймеру:
  мобильные браузеры замораживают таймеры сразу после сворачивания, и отложенная запись
  не случилась бы никогда. Иначе service worker читал бы устаревшую сводку — например,
  старую дату последнего показа — и присылал второе напоминание за день.
  Пока страница на экране, запись по-прежнему с дебаунсом 1,2 с, чтобы не дёргать базу
  на каждое нажатие клавиши.

### Использование на телефоне
- Экран «На телефон» (`#/phone`) показывает QR-код адреса приложения, инструкции по установке
  отдельно для Android/Chrome и iPhone/Safari и объясняет требования HTTPS.
- QR-код генерируется локально своим кодировщиком (`js/qr.js`), без обращения к внешним
  сервисам — иначе адрес пользователя уходил бы на чужой сервер, а офлайн-режим ломался бы.
- Если открыт `localhost`, экран прямо предупреждает, что телефон по этому адресу не пройдёт,
  и приложение нужно сначала опубликовать на настоящем HTTPS-адресе.
- Телефон начинает с пустой базы: данные в `localStorage` не переезжают сами. Чтобы получить
  накопленные слова, на телефоне надо открыть `#/sync` и подключиться к хранилищу по коду
  (см. «Подключение второго устройства»).

### Интерфейс
- Тёмная и светлая темы, режим «как в системе».
- Адаптивность: на десктопе — сайдбар, на мобильных — нижний таббар; учитываются
  safe-area отступы iOS, размеры под палец, перестройка сеток.
- Озвучивание через Web Speech API: выбор голоса, темп, тон, громкость, подсветка слов.
- Горячие клавиши: `Пробел` — показать ответ/далее, `1`–`4` — оценка и выбор варианта,
  `Ctrl+Z` — отменить ответ, `R` — повторить озвучивание.
- Тосты, модальные окна, пустые состояния, обработка ошибок хранилища.

## Разработка

```bash
# быстрая проверка без браузера: контракт модулей, полнота SHELL у sw.js,
# юнит-тесты. Прогон перед любой выкладкой — ловит вызовы несуществующих
# функций и файлы, забытые в офлайн-кэше
node tools/check-contract.js
for t in core sync notify qr streak; do node tools/test-$t.js; done

# тесты ядра: повторение, утилиты, импорт/экспорт, конструктор промпта, озвучка,
# совет о голосах перед тренировкой, остановка речи при уходе с экрана,
# сетевая озвучка и пакет готовых файлов (402 проверки)
node tools/test-core.js

# слияние данных, провайдер GitHub Gist, подключение по коду приглашения
# и по коду хранилища, удаление на двух устройствах, срочная отправка
# и синхронизация при возвращении в приложение (349 проверок)
node tools/test-sync.js

# напоминания, расписание уведомлений и немедленная запись сводки
# при уходе в фон (157 проверок)
node tools/test-notify.js

# кодировщик QR-кодов (180 проверок)
node tools/test-qr.js

# серия дней: зачёт дня, обрыв серии, рекорд, остаток до продления
node tools/test-streak.js

# перегенерировать иконки
python tools/generate_icons.py

# собрать пакет озвучки: скачать MP3 для слов приложения в audio/ (нужен интернет,
# один раз). --data backup.json — озвучить свои карточки из резервной копии
node tools/build-audio-pack.js
node tools/build-audio-pack.js --data backup.json --force

# сквозная проверка всех экранов и режимов в браузере (нужен сервер на :8777)
NODE_PATH=<путь к node_modules с playwright> node tools/e2e-check.js

# тот же набор по опубликованному адресу
LEXIFLOW_BASE=https://<ваш-адрес>/index.html node tools/e2e-check.js

# быстрая проверка опубликованной версии: приложение открылось, ошибок нет,
# service worker встал, QR построен по публичному адресу, а не по localhost
NODE_PATH=<путь к node_modules с playwright> node tools/check-live.js https://<ваш-адрес>/index.html

# однофайловая сборка для телефона (открывается без сервера и без интернета)
node tools/build-mobile.js
NODE_PATH=<путь к node_modules с playwright> node tools/check-mobile.js

# синхронизировать папку для публикации (читает SKIP-список внутри скрипта)
node tools/sync-deploy.js
node tools/sync-deploy.js --dry-run

# скриншоты всех экранов (тёмная тема, десктоп + мобильный) → tools/output/
NODE_PATH=<путь к node_modules с playwright> node tools/screenshots.js
```

`tools/test-core.js` запускает модули `js/*.js` в Node с минимальным shim-окружением
(поддельные `document` и `localStorage`), поэтому сами модули менять не нужно.
Перед выпуском стоит прогонять все наборы: тесты ядра ловят ошибки в алгоритме
и парсерах, `check-contract.js` — вызовы несуществующих функций модулей и файлы,
которые подключены на странице, но забыты в `SHELL` у `sw.js` (без второго
приложение работает в онлайне и молча ломается после перезагрузки без сети),
а сквозная проверка — регрессии в интерфейсе.

Приложение не требует сборки: правки в файлах видны после перезагрузки страницы.
При изменении списка файлов не забудьте обновить `SHELL` в `sw.js` и версию `VERSION` —
за этим следит `node tools/check-contract.js`, он же падает, если файл забыт.

## Данные и приватность

Всё хранится в `localStorage` браузера под ключом `lexiflow.data.v1`.
Очистка данных сайта в браузере удалит прогресс, поэтому регулярно делайте
экспорт резервной копии на экране «Импорт / экспорт».

Сам код приложения никуда не отправляет колоды, слова и статистику. Наружу уходят
ровно три вещи, и все — по вашей команде:

- **GitHub Gist** — копия данных, только если вы включили синхронизацию; токен
  остаётся на устройстве и не попадает ни в гист, ни в резервную копию;
- **api.github.com** — тот же обмен, других адресов приложение не знает;
- **маячок хостинга** — площадка, на которой выложена опубликованная версия,
  добавляет в страницу свой счётчик показов (он видит адрес страницы и заголовок,
  но не содержимое `localStorage`). Это особенность бесплатного хостинга, а не
  код LexiFlow: скачайте папку и поднимите её своим сервером — и маячка не будет.

Озвучивание идёт через системный Web Speech API браузера: текст слов остаётся
на устройстве, синтез делает операционная система. Исключение — **сетевая
озвучка** (см. раздел «Озвучивание»): если нормального системного голоса нет,
приложение может скачать готовый звук, и тогда **текст фразы уходит на
`code.responsivevoice.org`** — сторонний бесплатный сервис синтеза речи.
Режим включается только при плохом системном голосе, выключается в настройках
одним переключателем, а скачанное остаётся на устройстве и дальше звучит офлайн.
Готовые файлы из `audio/` вообще не требуют сети.
