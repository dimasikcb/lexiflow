## 3. Вердикт: можно ли скачать голос из приложения

### НЕТ. Веб-страница не может скачать или установить голос.

Проверено в живом Chromium, не по памяти.

**Все свойства и методы `speechSynthesis` в этом браузере** (цепочка прототипов, `Object.getOwnPropertyNames`):

```
Собственные свойства объекта:  []  (пусто)
SpeechSynthesis.prototype:     cancel, constructor, getVoices, onvoiceschanged,
                               pause, paused, pending, resume, speak, speaking
EventTarget.prototype:         addEventListener, constructor, dispatchEvent,
                               removeEventListener, when
```

Метода установки, загрузки или добавления голоса **нет**. `when` — это метод `EventTarget`, не имеет отношения к голосам.

**Все свойства `SpeechSynthesisVoice`** (на экземпляре голоса):

```
constructor, default, lang, localService, name, voiceURI
```

**Создать голос вручную нельзя:** `new SpeechSynthesisVoice()` → `TypeError: Failed to construct 'SpeechSynthesisVoice': Illegal constructor`.

Поиск по именам методов, похожих на установку (`install|download|add|fetch|import|register|purchase|store|upgrade|enable|acquire`), дал **единственное совпадение — `addEventListener`**. Никаких `installVoice`, `addVoice`, `downloadVoice`, `fetchVoice` ни в спеке, ни в браузере нет.

Спецификация Web Speech API определяет у `SpeechSynthesis` только `speak`, `cancel`, `pause`, `resume`, `getVoices`, свойства `paused`/`pending`/`speaking` и событие `voiceschanged` (MDN: <https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis>). Возможности установки голоса в ней нет вообще.

### (а) Невозможно никогда

* Скачать, установить или добавить голос из веб-страницы.
* Сделать так, чтобы `getVoices()` вернул голос, которого нет в системе.
* Вызвать загрузку TTS-движка или пакета голосов.
* Узнать, идёт ли установка голоса, и дождаться её окончания.

### (б) Возможно только через систему

* Открыть системный экран настроек, где пользователь сам поставит голос. Это единственный реальный путь, и он зависит от платформы (см. раздел 4).
* Страница не может ни выполнить установку, ни проверить её ход — только предложить ссылку и потом перечитать список голосов.

### (в) Возможно прямо из приложения

* Понять, какие голоса есть, а каких нет, — `getVoices()` (уже используется).
* Честно сказать пользователю, какого языка не хватает, и назвать точный путь в настройках для его платформы.
* Дать кнопку-ссылку, открывающую системный экран настроек (где платформа это разрешает) — только по жесту пользователя.
* Перечитать список голосов после `voiceschanged` и по возвращении на вкладку, и обновить вердикт без перезагрузки.
* Дать кнопку «Проверить снова» и, при необходимости, предложить перезагрузку страницы.
* Порекомендовать Edge с голосами Natural (уже реализовано в `tools.js:190–198`).

## 4. Точные способы инициировать установку по платформам

| Платформа | Строка / путь | Статус |
|---|---|---|
| **Windows** | `ms-settings:speech` — страница «Речь» (Время и язык → Речь), где добавляются голоса | URI **документирован** Microsoft (из документации). Открытие **из браузера** — **не подтверждено** (см. ниже) |
| **Android** | `intent:#Intent;action=com.android.settings.TTS_SETTINGS;end` | **Не проверено** — на этой машине нет Android. Синтаксис `intent:` и требование жеста — из документации Chrome |
| **macOS** | `x-apple.systempreferences:com.apple.preference.universalaccess?SpokenContent` (Универсальный доступ → Устный контент) | **Не проверено** — нет macOS. Из документации сообщества |
| **iOS** | URI нет. Только вручную: Настройки → Универсальный доступ → Устный контент → Голоса | **Не проверено**. Путь — из документации Apple |
| **Microsoft Edge, голоса Natural** | Отдельный случай: голоса приходят из сети, установка не нужна | **Не проверено** — Edge на машине нет |

### Что именно проверено на этой машине (Windows, Playwright Chromium)

Контрольный опыт доказал, что метод детекции рабочий: неизвестная схема и `mailto:` дают в консоли `Not allowed to launch '<схема>' because a user gesture is required.`, а с жестом — `Failed to launch 'unknown-scheme-xyz:foo' because the scheme does not have a registered handler.`

| Схема | Без жеста | С жестом | Открылись ли «Параметры» |
|---|---|---|---|
| `ms-settings:speech` | сообщения в консоли **нет** (молча проигнорировано) | сообщения в консоли **нет** | **нет** — новый процесс `SystemSettings.exe` не появился (опрос 6 с, PID до и после пусты) |
| `ms-settings:easeofaccess-speech` | `Not allowed to launch ... user gesture is required` | сообщения нет | **нет** |
| `unknown-scheme-xyz:foo` (контроль) | `Not allowed to launch ...` | `Failed to launch ... no registered handler` | — |
| `mailto:` (контроль) | `Not allowed to launch ...` | — | — |

Итог по Windows: **достоверно подтвердить, что клик по `ms-settings:speech` открывает «Параметры» из браузера, не удалось.** Результаты противоречивы: в одном прогоне процесс `SystemSettings.exe` присутствовал после серии опытов с протоколами, в целевом прогоне с отслеживанием PID — не появился ни разу. Отсутствие ошибки «Failed to launch» у `ms-settings:speech` (в отличие от контрольной неизвестной схемы) можно трактовать как признак того, что схема зарегистрирована в системе и Chromium её передал ОС, но это косвенный признак, а не подтверждение. Отдельно: проверка реестра (`HKCR\ms-settings`) **не выполнена** — `reg.exe` заблокирован политикой безопасности, PowerShell в этом окружении не возвращает вывод.

Существенная оговорка: это **Playwright-сборка Chromium**, а не браузер, в котором работает пользователь. Поведение настоящих Chrome/Edge может отличаться. Microsoft документирует URI `ms-settings:*` **для приложений** (WinRT `LaunchUriAsync`, XAML `Hyperlink`), а не для веб-страниц: <https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings>. Именно там `ms-settings:speech` указан как страница «Speech» в разделе Time and language.

### Требование жеста пользователя

Проверено: Chromium отказывается запускать внешнюю схему без жеста пользователя (`Not allowed to launch ... because a user gesture is required`). Это подтверждает и документация Chrome для Android: «Chrome won't launch an external application ... A JavaScript timer tried to open an application without a user gesture» (<https://developer.chrome.com/docs/android/intents>). Синтаксис intent-ссылки оттуда же: `intent:` + необязательный хост/путь + `#Intent;action=...;end;`. Там же есть механизм отката `S.browser_fallback_url=<url>` — полезен, если intent не разрешился.

Важно: `action=com.android.settings.TTS_SETTINGS` взят из постановки задачи. **На реальном устройстве не проверялся**, точное значение константы подтвердить по авторитетному источнику не удалось (developer.android.com отдаёт редирект на OAuth и недоступен для чтения).

### Рекомендация по разделу

Ссылки на системные настройки давать **только как «откроется системный экран, если платформа это поддерживает»**, всегда с текстовой инструкцией-дублёром и никогда не обещать, что голос после этого появится сам. Кнопка обязана быть обычным кликом пользователя, не программным переходом.

## 5. Подтверждение установки: как узнать, что голос появился

### Что проверено

| Проверка | Результат |
|---|---|
| `voiceschanged` срабатывает при загрузке | **Да**, 1–2 раза за загрузку. Одно из срабатываний может прийти с пустым списком (`count 0`) |
| `getVoices()` перечитывает список при каждом вызове | **Нет.** Список кэшируется в рендерере: массив каждый раз новый, но объекты голосов — **те же самые ссылки** (`a[0] === b[0]` → `true`) |
| `speechSynthesis.cancel()` обновляет список | **Нет.** После `cancel()` длина списка и число событий не изменились |
| `visibilitychange` / `focus` заставляют приложение перечитать голоса | **Нет.** При синтетических `visibilitychange` и `focus` приложение вызвало `getVoices()` **0 раз**. В коде это подтверждается: `js/speech.js:700` на `visibilitychange` вызывает только `stopWhenHidden` (остановку речи), обновления голосов там нет |
| Обновляется ли вердикт при изменении списка | **Да.** Симуляция: подменили `getVoices()` и отправили `voiceschanged` — `App.speech.voices()` сразу вернул новый список, `voiceAdvice(['de'])` вернул `null` (тревога снята), `voiceQuality` → `neural`. Механизм `speechSynthesis.onvoiceschanged = refreshVoices` (`js/speech.js:92`) рабочий |

### Что НЕ проверено и почему

**Сработает ли `voiceschanged` после того, как пользователь установил голос и вернулся в приложение, — не проверено.** Причины:

* установить голос в системе и изменить реальный список `getVoices()` в ходе аудита невозможно;
* получить настоящее событие `visibilitychange` в автоматизации не удалось: Playwright держит все страницы в состоянии `visible` (проверено и в headless, и в headed, и даже с отключёнными флагами `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding`, `--disable-background-timer-throttling`). CDP-метода `Emulation.setPageVisibilityOverride` в этой сборке нет (`wasn't found`).

### Практический вывод

`voiceschanged` — единственный официальный сигнал, что список изменился (MDN: <https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/voiceschanged_event>). Но полагаться только на него нельзя: событие не сработало ни на `cancel()`, ни при возврате на вкладку в проверенных сценариях, а список кэшируется.

Надёжная схема — комбинация:

1. Слушать `voiceschanged` через **`addEventListener`** (не через `onvoiceschanged`: `js/speech.js:92` уже занимает это свойство, присваивание его перезапишет).
2. Игнорировать события с нулевым списком, продолжать слушать.
3. Перечитывать `App.speech.voices()` при возврате на вкладку — на `visibilitychange` со `visibilityState === 'visible'` и на `window.focus`. Это дёшево и безопасно.
4. Дать кнопку «Проверить снова» для ручной перепроверки.
5. Если после перечисленного список по-прежнему пуст — предлагать **перезагрузку страницы**, потому что гарантированно подхватить новый голос без перезагрузки **не проверено**.

## 6. Рекомендация для реализатора

1. **Не делать кнопку «Скачать голос».** Скачать или установить голос из веб-страницы невозможно — ни в этом браузере, ни в спеке. Кнопка будет неработающей.
2. **Не обещать в тексте, что голос появится сам.** Максимум — «откроется системный экран, установите голос там, затем вернитесь и нажмите „Проверить снова“».
3. **Исправить формулировку «кнопка 🔊 будет молчать»** в `voiceAdvice` (`js/speech.js:229`) и в подсказке `voiceQuality` (`js/speech.js:178`). Проверено: кнопка есть всегда и Chrome произносит текст голосом по умолчанию, то есть **чужим произношением**, а не молчит. Разница для пользователя принципиальная.
4. **Добавить `App.speech.installPlan(langs)`** — чистую функцию без побочных эффектов, возвращающую данные, а не разметку (по образцу `voiceAdvice`): для каждого языка — `{ lang, count, best, level, action }`, где `action` — один из `{ kind: 'none' }` (всё в порядке), `{ kind: 'link', href, label }` (есть проверенная ссылка), `{ kind: 'manual', path }` (только текстовая инструкция).
5. **Ссылки на настройки давать по платформе и помечать честно.** `ms-settings:speech` — Windows (документированный URI, из браузера **не подтверждён**). Intent на Android (**не проверено**, нет устройства). `x-apple.systempreferences:com.apple.preference.universalaccess?SpokenContent` — macOS (**не проверено**). iOS — только текстовая инструкция. Везде дублировать текстом и оборачивать переход в `try/catch`.
